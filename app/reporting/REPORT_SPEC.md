# Project Expert AI — единый контракт отчёта

## Назначение

Это единственная точка, которая определяет, что считается пользовательским результатом нормоконтроля.

Внутренние результаты проверки могут содержать факты, `compliant` и `unchecked`. Они нужны для трассируемости и дальнейшего анализа, но не являются замечаниями.

## Цепочка

`Skill → извлечение факта → нормативный Router → RAG → нормативное требование → сравнение → решение → report_contract → вкладки «Замечания» / «Отчёты» / PDF / Word`

## Что является замечанием

Только результат с:

```text
type == "violation"
```

Для замечания обязательны:

- номер;
- лист/страница;
- параметр;
- значение в исходнике;
- конкретное нормативное требование;
- СП и пункт;
- результат «Нарушение»;
- рекомендация;
- доказательство — изображение исходного фрагмента с красной рамкой.

## Что НЕ является замечанием

### `unchecked`
Недостаточно доказательств для вывода. Такой результат не должен попадать в реестр замечаний. Он хранится в `review_results`.

### `compliant`
Подтверждённое соответствие. Хранится в `compliant_results` и может использоваться в общей оценке, но не является замечанием.

## Публичная модель отчёта

`results` — только подтверждённые замечания.

`remarks` — то же самое, явное имя для UI.

`review_results` — результаты, требующие дополнительной экспертной проверки.

`compliant_results` — подтверждённые соответствия.

`summary` содержит отдельные количества:

- pages;
- violations;
- critical;
- major;
- minor;
- compliant;
- unchecked.

## Трассируемость

Номер замечания и номер изображения должны соответствовать друг другу: замечание №1 → изображение №1.

`evidence_image` и `image` принадлежат тому же finding, из которого построено замечание.

## Запреты

1. Нельзя использовать `description` как замену нормативному требованию.
2. Нельзя показывать номер СП без конкретного пункта там, где требуется нормативное основание.
3. Нельзя превращать обнаруженный проектный факт в нарушение без подтверждённого нормативного сравнения.
4. Нельзя смешивать внутренний диагностический список кандидатов с реестром замечаний.
5. Все пользовательские представления должны получать данные через `prepare_public_report()`.

## Связь со Skill

Skill отвечает за предметную экспертизу: что искать, какие факты извлекать, какие СП применять, какие условия считать достаточными для `violation/compliant/unchecked` и какие доказательства обязательны.

Отчётный контракт отвечает за единое представление результата этого Skill.

Таким образом, Skill не должен отдельно генерировать HTML, PDF или таблицу. Он формирует экспертное решение, а отчётный слой превращает решение в единый пользовательский отчёт.
